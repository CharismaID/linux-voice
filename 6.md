### 1. Перенаправление потоков и особенности работы Bash

#### **Объективное знание**

* **Стандартные потоки I/O:**
* `0` (`stdin`) — стандартный поток ввода.


* `1` (`stdout`) — стандартный поток вывода.


* `2` (`stderr`) — стандартный поток ошибок.




* **Порядок обработки команд в Bash:**
* Конструкции с перенаправлением вывода (например, `> filename`) интерпретируются интерпретатором Bash **справа налево**.


* При использовании оператора `>` Bash сначала подготавливает файл (создаёт его или обнуляет его размер до 0 байт), и только после этого запускает команду, стоящую слева.


* При использовании оператора `>>` файл не обнуляется; данные дописываются в конец существующего файла после выполнения команды.




* **Перенаправление потока ввода (`stdin`):**
* Оператор `<` перенаправляет содержимое файла на стандартный поток ввода программы (например, `mysql -u root -p database_name < dump.sql`).


* Не все утилиты умеют работать с прямо перенаправленным `stdin` (например, `ls` принимает аргументы, но не читает напрямую из `stdin`).





#### **Комментарии лектора**

* Конструкция `cat file1 file2 > file3` склеивает содержимое нескольких файлов в один.


* Поток ввода `stdin` через оператор `<` чаще всего применяют для восстановления баз данных из SQL-дампов.



#### **Мудрость лектора**

> * **Нельзя перенаправлять вывод команды в тот же файл, из которого она читает!**
> 
> 
> Попытка выполнить команду вида `tail -n 20 log.txt > log.txt` приведет к полной потере данных. Так как Bash обрабатывает перенаправление справа налево, файл `log.txt` сначала полностью обнулится (станет 0 байт), и команда `tail` будет читать уже из пустого файла. Для таких операций нужно использовать временные файлы или переменные.

### 2. Конвейеры (Pipes) и просмотр данных (`less`)

#### **Объективное знание**

* **Конвейер (`|`):**
* Символ `|` (pipe) перенаправляет `stdout` (поток вывода) первой команды на `stdin` (поток ввода) второй команды: `cmd1 | cmd2`.


* Конвейеры можно объединять в длинные цепочки из множества команд.




* **Утилита `less`:**
* Позволяет постраннично просматривать вывод или содержимое файлов с помощью навигации (стрелки `Вверх`/`Вниз`, `PageUp`/`PageDown`).


* Для выхода из утилиты `less` используется клавиша `Q`.





#### **Комментарии лектора**

* Длину конвейеров можно наращивать практически без ограничений — всё упирается только в объём оперативной памяти, забить которую текстом на современных ПК почти невозможно.


* Если стандартный справка (`--help`) выдает слишком много текста и отправляет его в поток ошибок (`stderr`), его можно отфильтровать, перенаправив `stderr` в `grep`.



#### **Мудрость лектора**

> * Философия Unix построена на передаче данных между утилитами: одна программа делает свою часть работы и передает результат следующей. Выстраивание цепочек через конвейер (`|`) — это фундаментальный навык для написания скриптов и автоматизации.

### 3. Утилиты фильтрации и анализа текста (`head`, `tail`, `wc`, `grep`)

#### **Объективное знание**

* **Вывод частей файла (`head` / `tail`):**
* `head -n <число>` — выводит первые $N$ строк файла (по умолчанию 10).


* `tail -n <число>` — выводит последние $N$ строк файла.


* `tail -f <файл>` — удерживает файл открытым и выводит новые строки в режиме реального времени по мере их поступления.




* **Подсчет элементов (`wc`):**
* `wc -l` — подсчитывает количество строк (`lines`).


* `wc -w` — подсчитывает количество слов (`words`).


* `wc -m` / `wc -c` — подсчитывает количество символов.




* **Поиск по шаблону (`grep`):**
* Ищет указанные текстовые шаблоны в файлах или потоке вывода.


* `grep -v` — инвертирует поиск (выводит строки, **не содержащие** указанный шаблон).





#### **Комментарии лектора**

* Название утилиты `grep` происходит от команды древнего строчного редактора `ed`: `g/re/p` (*Global / Regular Expression / Print*).


* При работе с `head` или `tail` флаг `-n` использовать предпочтительнее, чем просто `-3`, так как `-n 3` позволяет свободно комбинировать его с другими ключами утилиты.



#### **Мудрость лектора**

> * Команда `tail -f` — незаменимый инструмент любого системного администратора. Когда пользователь жалуется, что не может авторизоваться, открывайте лог через `tail -f` и смотрите попытки входа в реальном времени: вы сразу увидите, где ошибка — в неверном логине (`invalid user`) или пароле (`invalid password`).

### 4. Управление файлами и работа в терминале

#### **Объективное знание**

* **Копирование и перемещение:**
* `cp <источник> <назначение>` — копирует файл или каталог.


* `mv <источник> <назначение>` — перемещает файл или используется для его переименования.




* **Основы редактора Vim:**
* Выход из текстового редактора Vim выполняется путем ввода `:q` (или `:q!` для выхода без сохранения) и нажатия `Enter`. Комбинация `Ctrl + C` из Vim не выводит.


* Нажатие `Ctrl + Z` не закрывает программу, а отправляет её процесс в фоновый режим.





#### **Комментарии лектора**

* Команда `mv` не имеет отдельного аналогичного бинарника для "переименования" — перемещение и переименование в Linux суть одна и та же операция.


* При сдаче домашних работ лучше отправлять текстовые логи команд, подключившись по SSH, чем пытаться настроить буфер обмена в графическом окне виртуальной машины.



#### **Мудрость лектора**

> * Не бойтесь ошибаться при выполнении практических заданий. Полноценно сделанная самостоятельная работа с ошибками гораздо ценнее для обучения, чем идеально скопированное чужое решение.
